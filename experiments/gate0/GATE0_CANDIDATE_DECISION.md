# Gate 0 候选任务裁定

**版本：** r81 之后（2026-11-16）
**状态：** 裁定建议，**不构成实验授权**。正式 Gate 0 仍需预注册与独立裁定；本文件不开启 Gate 1。

---

## 0. 结论

Gate 0 现在卡在**仪器**上，不在任务上。

在当前实现里，"奖励"从来没有投递给产生它的那一轮事件：42–44% 的答案通路事件发生在
写奖励之前，拿到的是上一轮的结果；其余事件发生在读出之后，对它们被归因的那次结果没有贡献。
而在默认能量标尺下，赢家组在事件时刻读到的奖励**低于**输家组（23 轮里只有 4 轮方向正确，
均值 −0.040）。

因此在投递被修好并验证之前，**任何场地上的任何机制比较都不能解释**——包括"任务太难"、
"任务太简单"、"机制无效"这一类判断。上一轮"场地供给答案"的结论仍然成立，但它不是当前
最紧的约束；最紧的约束在它上游。

## 2. 三条证据

同一条命令、同一种子（411）、`w_p8=0.05`、窗口 20–70 ms、`arm='local'`，3 试次共 24 轮。

| # | 读什么 | 读数 | 含义 |
| --- | --- | --- | --- |
| E1 | 写奖励之前发生的 ACT 群脉冲占比 | **42.5%**（global）／**44.3%**（act） | 这些事件拿到的是上一轮的结果 |
| E2 | 事件时刻"赢家组奖励 − 输家组奖励"的均值 | **−0.040**（global，方向正确 4/23） | 默认标尺下奖励与结果反相关 |
| E3 | 同上，改用局部标尺 | **+0.204**（act，方向正确 17/23） | 换标尺能救一半，但救不了"晚一轮" |

E2 的机制不是噪声而是饱和：决策时写入把赢家组能量设成 `med + s·r*·scale`（读回恰好
`+0.500`），而未处理的输家组能量远高于全群中位数、被 clip 在 `+1.000`。**赢家拿到的奖励
比输家少**，且在结果错误的那几轮里，拿到较大奖励的是正确组。

完整记录与判词：`records/diagnostics/2026-11-16_r81_reward_delivery.md`。

## 3. 为什么"闸 0 字面 ≤ 0.70"不再算通过

0.647 这个基线来自一个**不投递奖励**的臂，和一个**由接线供给答案**的场地：

- 基线由 `w_p8` 的接线强度决定（0.562 → 1.000 随 `w_p8` 单调），不是由学习决定；
- `local` 与 `task_off` 的差异在这种条件下没有可解释的含义。

"基线 ≤ 0.70"只保证"任务没被接线一次解掉"，**不保证这个 0.70 与学习机制有关**。路线把它
当 headroom 门槛是对的；错在把它同时当成了测量合格证。这两件事必须分开：

| 门槛 | 问的是 | 谁负责 |
| --- | --- | --- |
| 准确率 ≤ 0.70 | 还有没有提升空间 | 任务设计 |
| 奖励是否按轮投递 | 提升能不能被归因于奖励 | 仪器自检 |

第二项此前从未做过，而它先于第一项。

## 4. 本轮修了什么（已交付、已验证）

新增开关 `credit.at`，默认 `'event'`（历史行为，权重指纹逐位不变：`830136398b09fbed`，
7200 边，`w_sum=1592.799952`）。

`'decision'` 模式：

1. 每轮开始时清空逐边资格迹；
2. 每次突触事件只累积资格迹（`e -= A₋·y_post` 于该细胞入边，`e += A₊·x_pre` 于其出边），**不乘奖励**；
3. 决策时一次性施加 `dw_ij = R_j · e_ij`，其中 `R_j = ±r*` 仅对被选组，其余**精确为 0**；
4. 更新仍是"每细胞一个标量 × 每边一个资格迹"——秩一结构、`dw(+1)=−dw(−1)`、无时序窗口
   这些**结构性结论一条都没有被改动**，改的只是第三因子的读取时刻。

验证脚本 `experiments/gate0/code/credit_delivery_check.py`，五条全过：

| 检查 | 内容 | 结果 |
| --- | --- | --- |
| C1 | 关闭时权重指纹 | `830136398b09fbed`，与记录逐位相同 |
| C2 | 决策之间不得写权重 | 决策后连续 3 ms 的 `\|dw\|` 全为 `0.0` |
| C3 | 学习轮必须真的到达 | 4/4 学习轮发生写入 |
| C4 | 写入必须只落在被选组 | 组外 `\|dw\|` **精确 0.000e+00** |
| C5 | 零对照 | 探针轮、`task_off` 的 `\|dw\|` 全为 `0.0` |

C4 是这条开关可信的关键：它说明"信用落在哪"由**本轮结果**决定，而不是由扰动决定。

一个附带事实：`'decision'` 模式下 `task_off` 是**精确冻结**网络（`dw ≡ 0`）；`'event'`
模式下它不是——它会跟着自然能量场学。此前"`task_off` 也在学"的记录，正是这个原因。

## 5. 场地问题没有被这次修复解决

- 上一轮结论仍成立：答案由 `p8` 接线供给，写入量与准确率同向，打乱分配比正确分配还高。
- 修复带来的唯一改善是：现在"`local` 比 `task_off` 高"第一次可以只归因于**被投递的奖励**，
  而不是"自然能量场也在学"。
- 但"把写入的量做大"仍然能让准确率上升，因此**信用质量**仍不可测。

⇒ 场地仍然必须满足：**正确的那条边随试次变化**。

修复后的第一次配对跑（探索性，8 种子，无预注册）见
`results/summaries/2026-11-16_r81_credit_modes.md`：`decision` 模式下零对照臂精确冻结、
学习臂写入 2.47（其中只有 **0.5 落在载体上**），行为差 **+0.023**、MDES **0.073** ⇒ 未判定。
同一批里 `event` 模式的零对照臂反而写了**更多**载体（5.1 对 2.4）——旧的臂比较连"哪个臂
拿到的写入更多"都没有对上名字。

## 6. 候选 D（新提）：随试次变化的正确边

### 6.1 规格

| 项 | 定义 |
| --- | --- |
| 每轮输入 | `cue c ∈ {0,1}`（由哪条刺激通道注入决定）；`instruction m ∈ {0,1}`（标记通道 2/3） |
| 目标 | `target = c XOR m` |
| 表示 | 4 个合取细胞 `H_{c,m}` 作为基础设施：只接对应 cue 与指令的输入细胞群（与 `p8` 同类的手工通路） |
| 可塑部分 | **只有 `H → ACT` 的 8 条边**，初始 8 条严格等权（并列） |
| 读出 | 不变：窗口内两动作群脉冲计数多者胜 |
| 奖励 | 修复后的按轮投递；被选组 `±r*`，其余 0 |

### 6.2 为什么它满足可识别性（代数，不是统计）

1. 8 条边等权 ⇒ 每个 `H_{c,m}` 对两个动作群驱动相同 ⇒ **并列** ⇒ 准确率 = 0.5（由噪声打破并列）。
2. 任何**均匀**写入（总增益 ×k、打乱分配、把学习率调大）都保持并列 ⇒ 准确率仍 0.5。
3. 只有"按轮的、指向被选组的差分写入"才打破并列。

因此"写入量"不再是准确率的充分统计量——这正是上一轮缺的那条性质，而且它是**精确**性质
（并列），不依赖显著性检验。

### 6.3 五个检查与状态

| 检查 | 判据 | 状态 |
| --- | --- | --- |
| 可表达性 | 手工把 8 条边设成正确符号 ⇒ 准确率 ≥ 0.95 | 待做（实现后第一条要跑的就是它） |
| 可识别性 | 等权基线 0.5；均匀放大 ×k 后仍 0.5 | 待做 |
| Headroom | 现机制最优臂 ≤ 0.70 | 待做（预期 ≈0.5） |
| 正对照 | 同一场地、同一条读出下，存在一个已知方法学会 | 待做（可用修复后的按轮信用作正对照） |
| 成本 | 与现场地同量级 | **已满足**（同一仿真回路，12 试次 ≈ 60 s） |

### 6.4 代价与风险

- 它预设了**合取表示**（4 个 `H` 细胞是给的）。因此它测的是信用，不是表示；若机制在此失败，
  结论是"信用不足"，**不能**读成"网络无法表示该任务"。
- `H` 细胞是基础设施，但与 `p8` 有本质区别：`p8` 提供的是答案（初始就正确），`H` 提供的是
  表示（初始等权 ⇒ 0.5）。
- **它必须在 §4 之后实现**：正确边随试次变化，就要求奖励属于本轮；晚一轮的投递在这里不是
  变慢，而是学到错轮。

## 7. 路线的 A / B / C 怎么处理

| 候选 | 改什么 | 为什么不先做 |
| --- | --- | --- |
| A：第三条指令通道 | 指令信息与驱动信息分离 | 不改变"答案由接线供给"，只增加容量与捷径；可识别性不变 |
| B：两套 cue 特异权重 | 不同 cue 形成独立学习路径 | 直接提高参数量，必须做参数量匹配对照；不解决可识别性 |
| C：比较器读出 | 换决策读出 | 路线自己标注的风险："读出变化可能改变任务本身或掩盖网络问题" |
| **D：随试次变化的正确边** | 目标 = cue × 指令的合取 | **唯一直接针对可识别性**的一条；其余三条都绕开它 |

不预设 D 会成功。D 的失败方式也有信息：若"精确并列 + 按轮投递"下机制仍停在 0.5，那就把
问题从"场地不可识别"收敛成"这个信用规则确实不区分边"，后者才是 Gate 1 该问的。
